## 4. 指南针精度问题 — 本轮核心（全部结论已推导完成）

### 关键实验结论（勿再重复实验）
1. **设备坐标系**（加速度计平放验证）：`+Z = 屏幕朝里`（平放 az≈-9.8 → 上=出屏）。右手系，因此 12 点方向、3 点方向由此确定。
2. **陀螺仪**：gz>0 = 俯视顺时针（与航向增加一致）
3. 北半球平放时**磁力计 Z 与设备 Z 反向**（原始 mz 为负大值）
4. **磁→设备映射（已实施）**：`(X_dev, Y_dev, Z_dev) = (-mx, +my, -mz)` —— MMC5603NJ 芯片相对 IMU 绕 Y 轴 180° 安装。det=+1 确认为合法旋转（物理唯一）
   - 依据：北/南两姿势差分实验。北 mx=-32.0 my=+5.5 mz=-70.9；南 mx=-7.1 my=-4.0 mz=-72.3；校正残差后两姿势磁方向互为 180° ✓
   - 此映射下：北→350°、南→159°（与 0°/180° 有 ~21° 系统性偏差 = 手机室内指南针参考误差 + 对准误差 + 校准残留，可接受；后续可加固定偏置精调）
5. **加速度计符号坑（Madgwick 已弃用的原因）**：Madgwick 期望平放时 az=+1g（NED），本板物理上是 -9.8（加速度计测量的是 proper acceleration=-g）→ 喂 Madgwick 会收敛到错误姿态 → **这就是"与手机相差巨大"的元凶之一**

### 新融合方案（sensor_manager.c 实际状态，8/19 23:15 版）
- **主路径：xioTechnologies/Fusion AHRS**（`src/fusion/Fusion*.c/h`，已在 CMakeLists 里）：`FusionConventionNed`，`FusionAhrsUpdate`（静止时磁力计参与）/`FusionAhrsUpdateNoMagnetometer`（运动时纯陀螺），`FusionQuaternionToEuler` 取 yaw。2Hz 诊断打印 Fusion yaw/roll/pitch。
- 传感器输入约定：加速度计取反（`-a`）喂入 NED（本板物理上平放 az=-9.8）；磁力计已由驱动映射到设备坐标系（见下）。详见 sensor_manager.c 73-123 行注释与 586-680 行。
- sim 路径保留 `tilt_compass_heading()`（确定性倾斜补偿）做对照。
- 运动处理：静止/慢速时 Fusion 用磁力计校正；快速摇晃时仅用陀螺（`FusionAhrsUpdateNoMagnetometer`），避免"剧烈摇晃就乱".

### 磁力计读取路径（mag_mmc5603.c 本地已改）
- 读原始 counts → 减 hard-iron offset → ×0.00625 µT/LSB → ×OTP 补偿 → **×soft-iron scale（原来算了但从未应用！已修复）**
- 然后施加轴重映射 (-mx, +my, -mz) → 输出已是设备坐标系
- 校准（figure-8 min/max 法）：起始偏移 8000→15000ms（pages.c 两处双击已改）

### 校准持久化难题（已解决，方案=烧进固件）
- **`/data` 是 tmpfs（RAM），重启全丢** —— 这就是之前每次开机 cal=0 的原因
- 尝试 littlefs 挂 /dev/config0（NOR FS_REGION 0x9A0000-0xDA0000 4MB）：**失败**。运行时 NOR 写/擦除在 XIP 构建上 hardfault（回溯显示崩在 HAL_Init，中断上下文，arm_doirq→HAL_Init）；且厂商固件本来就"skip HAL_FLASH_Init during XIP bringup, NOR write/erase disabled"。（已全部回退，无残留）
- **最终方案：编译期默认校准**。mag_mmc5603.c 顶部 `MAG_CAL_DEFAULT_OX/OY/OZ/SX/SY/SZ` 宏（当前值 = 上会话 8s 校准结果 `(-3048, 3101, -9498)` counts，scale=1）。KV（tmpfs）有值则覆盖（会话级），重启回默认
- `kv_store.c` 已回退为纯 tmpfs /data/app_kv.txt（带注释说明为什么放弃 littlefs）
- **注意**：MAG_CAL_DEFAULT_* 宏是刚才（交接前）刚加的，**本地未重新编译、未同步 VM、未烧录**

## 真 bug 修复：KV 存储覆盖写损坏（2026-09，已上板验证）

**现象**：统计页永远 `NO RUNS YET`；设置项（亮度/单位/磁偏角）与磁校准 KV 覆盖值在重启后（本应保留到重启前）读回全是 0/默认值。

**根因**：`src/kv_store.c` 的 `kv_set_str()` 替换分支算错前缀长度——`kv_find()` 返回的是**值**指针（`p + keylen + 1`），而代码直接用它当"键起始"来算 `prefix`，于是把 `key=` 连同新行一起写了两遍：

```
# 错误产物（实测 /data/app_kv.txt）
probe.k=7|run.0.d=run.0.d=63300|run.count=run.count=1|...
```

`kv_find()` 仍能匹配该行（行首是 `run.count=`），但返回的值变成 `run.count=1` → `strtol` = **0**，于是 `run.count` 永远读到 0 → 历史为空、设置不生效。

**修复**：替换分支前缀改为
```c
prefix = (size_t)(vstart - s_kv_buf) - strlen(key) - 1;   /* 回退到键首 */
```
修复后实测：`demo seed: 5 runs in the history`，文件为干净的
`run.0.d=63300|...|run.count=5|...`，统计页正确显示 5 次记录与合计（134 MIN）。

**注意**：KV 文件在 `/data/app_kv.txt`，`/data` 是板级 bringup（`sf32li_ap.c`）挂载的 **tmpfs**，所以 KV 天然是**会话级**（重启即失，NOR 写入在 XIP 构建下会硬错，故不落盘）。

**演示数据开关**：`src/app_diag.h` 的 `APP_DEMO_SEED`（默认 **0**）。设为 1 编一次烧一次：开机自动写入 5 条记录并停在统计页；再烧回默认版即可（数据在 RAM 里，重启前一直有效）。

**截图**：`docs/images/ui-05-stats.png` 已替换为有数据的统计页实机抓帧。

## 指南针重做：6 轴方案 + 自证式验证（2026-09-17）

**决定**：产品路径**只用 6 轴（陀螺 + 加速度）**，磁力计不再参与航向。理由：本机磁硬铁误差最大 27 µT、
工作台环境磁场达地磁 3.7 倍，磁航向无法在当前环境获得可信验证。

**实现**：`src/attitude6.c|h`
- 滚转/俯仰由重力给绝对基准：`roll=atan2(−ay,−az)`、`pitch=atan2(ax,√(ay²+az²))`，与陀螺积分做互补滤波（时间常数≈1 s，首帧直接吸附）；
- 航向为**相对方位**：`yaw += −(ω·û)·dt`（û 为加速度计给出的“向上”方向），投影消掉了手腕绕前臂的摆动；带 ±0.6 °/s 死区；
- 零偏：静止（|a|≈1 g 且三轴角速度小）时学习并扣除；首次开机 + 之后约每 45 s；
- 原 `fusion/` 源码保留在仓库（备查），但**已从构建中移除**（CMakeLists 不再编译），产品不再使用 9 轴。

**自证式验证（关键，也是本次"先怀疑自己"的落点）**：模块内置**合成数据自检**（`attitude6_selftest()`），
用已知姿态 `a=(sinθ, −cosθsinφ, −cosθcosφ) g` 与已知竖直轴角速度生成输入，检查解算是否还原真值：
平放 / 右倾 30° / 左倾 45° / 抬头 40° / 滚转+俯仰 / ±90 °/s 偏航积分 / 带倾角转弯 30°、45° 共 9 个用例；
设备上执行 **`!att test`** 逐个打印 `[PASS]/[FAIL]`，并打印“未学习 1 °/s 零偏在 60 s 内的漂移”以如实呈现 6 轴固有漂移。

**被测试抓出的自身错误（记录在案）**：
1. 滚转符号写反：原 `roll=atan2(ay, √(ax²+az²))`；按实测（平放 az≈−9.47 m/s²、右倾 ay<0）应为 `atan2(−ay, −az)`；
2. 偏航积分符号写反：原用 `ω·û`（û 为“向上”）会把顺时针记成负；应为 `−ω·û`。

**新命令**：`!att`（打印 yaw/roll/pitch + 加速度参考值 + 角速率 + dt + 零偏状态）、`!att test`（合成自检）。
**验证脚本**：`tools/attitude_test.py`（物理协议：平放→右倾 90°→平放→顺时针 90°→静止，自动汇总 roll/pitch 极值、
yaw 总变化、滤波与加速度参考的偏差、静止段漂移）。
**UI**：指南针页改为 “6-AXIS REL” 相对罗盘，显示 ROLL/PITCH/RATE，中轴按钮为 **SET 0**（归零），设置页对应行改为 ZERO HEADING。

### 修复"静止时指南针还在动"（2026-09-18）

**症状**：手表静止不动时，指南针盘面仍缓慢爬动（每 20~30 s 跳约 1°）。
**实测定位**：3 分钟静止记录显示 `rate=0` 占 99.2%，但 yaw 仍漂 +3.7°（1.2 °/min）且呈**阶梯状** →
说明有**极少数陀螺尖峰样本**（幅值 >2 °/s，逃过静止门限）被当作真实转动积分（18 °/s × 0.05 s ≈ 0.9°/次，与台阶吻合）。

## 6 轴姿态改用官方 Fusion 链路 + 航向进入路线（2026-09-17 晚）

**起因**：用户要求"寻找 GitHub 官方做法"。官方仓库对"没有磁力计的航向"的答案就是
`FusionBiasUpdate`（静止门控零偏低通）+ `FusionAhrsUpdateNoMagnetometer`（四元数 + 半重力角度
残差反馈、角度门限的加速度拒绝带迟滞/恢复、启动增益斜坡、陀螺超量程软重启）+
`FusionQuaternionToEuler`。因此 `attitude6.c` 从"自写欧拉角互补滤波"改为**薄封装官方链路**
（API 不变，`sensor_manager.c`/`pages.c`/`ai_agent.c` 无需改动）。

**设置**：`FusionConventionNed`、`gyroscopeRange=2000 dps`、`accelerationRejection=15°`、
`rejectionTimeout=5 s`、`gain=0.5`；`FusionBias` 按 20 Hz 名义频率（3 °/s 门限、3 s 静止期）；
每帧按真实 dt 调 `FusionAhrsSetSamplePeriod()`（本仓 Fusion 是 e2e9cc0 基线，startup 斜坡按
`rate*samplePeriod` 递减 → 变 dt 正确，**不能**照抄上游 v1.3.3 的 startup 重构）。

**唯一保留的自研部分：输入毛刺预处理**（官方无对应机制：其 overrange 只在 ±1960 dps 附近触发，
抓不到本板 18–30 dps 的单样本读毛刺）。规则：单样本 >4×EMA+3 dps 丢弃；但**连续 3 个超阈样本
判为真实运动**并重新校准 EMA（150 ms 延迟）。

**自检（`!att test`，9 用例，ALL PASS）**——合成真值贯穿官方链路，另外固定了三个事实：
1. 官方 NED 的 roll/pitch 约定与本机实测**完全一致**（roll 正 = 右侧下压）；
2. 官方无磁路径**启动 3 s 内把航向强制归零**（"陀螺启动必须有确定 yaw"）→ 航向开机数秒后才有意义，
   自检用例必须先预热 4 s，否则 yaw 永远是 0（这一条就是自检抓出来的）；
3. **初版毛刺过滤会把"从静止开始的一次真实转身"整段吞掉**（EMA 停在 0 → 阈值 3 dps → 永远拒绝）
   → 自检的 `yaw ±60 dps` 用例抓到，加迟滞后 28/30 毛刺被挡且真实转动被跟随。
