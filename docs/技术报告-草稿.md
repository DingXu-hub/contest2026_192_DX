## 3.1 作品概述

**作品名称**：黄山派智能跑步手表（`contest2026_192_DX`，DX 队）

**一句话**：基于 openvela / NuttX 的 SF32LB52（黄山派）智能手表固件，具备 6 页现代化 UI、
**端侧 AI Agent（主动提醒 + 工具执行）**、经 PC 网关的可靠联网能力（时间同步 / HTTP / LLM），
以及**经物理自证的磁力计自校准**。

**硬件**：黄山派核心板（SF32LB52，Cortex-M33 双核 + 8 MB PSRAM）、390×450 AMOLED（RGB565）、
FT6146 触摸、LSM6DS3 IMU、MMC5603NJ 三轴磁力计、LTR303 环境光、CH340 串口（唯一对外链路）、
板载 MEMS 麦克风（bring-up 中）。

**软件规模**：应用源码 39 个文件（含 Fusion 融合库、AI agent、链路层），本地提交 19 项；发布固件
Flash 占用 34.6%、SRAM 39.3%。

## 3.2 系统架构与设计

**任务划分**（NuttX task）：`huangshan_render`（渲染/UI）、`huangshan_sensor`（IMU/磁/ALS 采样 + 融合）、
`huangshan_key`（KEY1/KEY2 翻页）、`huangshan_link`（**独占控制台**的帧化链路）、
`huangshan_ai`（AI Agent 心跳与主动引擎）、`huangshan_bt`（BT-PAN mock）。

**渲染**：直接写 RGB565 framebuffer（`/dev/fb0` mmap），自研 UI 工具层（圆润笔画数字、渐变弧、
胶囊按钮、发丝卡片、字距标签）；地图/轨迹由 `route_renderer` 绘制，纯色填充走 ePicasso GPU。

**AI Agent**：`ai_agent.c` 提供工具（`!start/!stop/!status/!timer/!tip/!link/!time/!http/!mic/!help`）与
**主动引擎**（定时提醒、空闲 3 分钟自动请求 LLM）；结果以"通知卡片"上屏。

**联网分层**（务实架构，见 3.3.3）：设备侧 `link.c`（帧协议） ⇄ PC 侧 `tools/gateway.py`
（帧编解码、时间同步、HTTP 代理、LLM、日志解复用）。

**安全与稳健**：控制台所有权仲裁（NSH 挂起）、发布版关闭诊断输出、磁力计异常时自动降级为纯陀螺（UI 显示 GYRO ONLY）。

## 3.3 关键技术实现

### 3.3.1 九轴姿态融合（xioTechnologies/Fusion v1.3.3）
- 单位与约定核对：陀螺 °/s、加速度 **g**（`/9.81`）、磁 µT；`FusionConventionNed`；机体轴 X=12 点/Z=屏内。
- **每帧用真实 dt** 调 `FusionAhrsSetSamplePeriod()`（循环约 19–33 Hz，非恒定）——为此**不能**照抄上游
  v1.3.3 的 startup 重构（它假定采样周期只设一次），保留旧数学并对变 dt 正确；同时手工移植上游 NaN 防护。

### 3.3.2 磁力计校准：从"拍脑袋偏移"到"物理自证"（本项目最有价值的技术点）
- **现象**：表盘航向乱跳、静止时 yaw 自己从 0° 走到 175°、指南针常显示"纯陀螺"。
- **定位**：逐行比对官方 Adafruit_MMC56x3 与 MMC5603NJ Rev.B 数据手册（寄存器协议全部正确：20-bit 解包、
  0.00625 µT/LSB、`TM_M|Auto_SR_en=0x21` 正是手册推荐值），再用 109 样本 3D 翻滚数据做**最小二乘球面拟合**：
  球心 (−4169,+1447,−5135) counts，**半径 47.5 µT = 当地地磁总场**（31°N）——物理自证。
- **根因**：旧固件把 Z 硬铁偏移当成"把地磁垂直分量吸收掉"的旋钮，导致 \|B\| 随朝向在 4.5–83.4 µT 之间变化
  （物理上不可能），Fusion 磁误差恒 90°。
- **修复**：烘入球心 + 软铁 scale；端上标定改为 LSQ 球面拟合 + **三重验收**（覆盖度 ≥2000 counts、
  半径必须 25–65 µT、RMS 偏差 ≤8%）。
- **实测**：`em` 90°→0–1°；\|B\| 35–56 µT（静止 σ=0.17 µT）；静止 yaw 稳定。
- **附带发现**：开发桌面存在 **184 µT 磁异常（地磁 3.7 倍）**，这是历史上"在桌面怎么标都不对"的根源——
  已写入文档提醒"标定/演示需远离桌面 1 m"。

### 3.3.3 联网：可靠帧协议 + PC 网关（并给出硬件边界证据）
- **硬件边界（实测）**：无 WiFi；蓝牙栈为 BLE-only（`BT_PERIPHERAL/CENTRAL`，无 `BT_BREDR`/`NET_BLUETOOTH`
  → **BT-PAN 不可能**）；唯一物理链路是 CH340 串口。
- **三个真实根因**：
  1. **NSH 交互 shell 抢占 `/dev/console`**（实测输入被 shell 执行、`msh >` 刷屏）→ 应用启动时
     `SIGSTOP` 接管；
  2. **控制台 RX 等效"1 字节深"**：63 字节突发仅 2–19 字符到达、4 字节一组只活最后 1 个、
     **逐字节 1 ms 间隔 63/63 零丢失** → PC 侧全部工具改为"逐字节节流写"；
  3. PC 端帧编码错误（CRC 只算帧头/载荷写两遍）→ 按设备端逐帧诊断修正并加编解码自检。
- **协议**：`AA 55 | TYPE | CH | SEQ | LEN | CRC16 | PAYLOAD | PAD`，通道 CTRL/TEXT/HTTP/FILE/IP(预留)，
  逐帧 ACK + 重传；应用层因此**永不丢命令**。
- **能力实测**：PING→PONG RTT 52–79 ms；**时间同步**（含时区偏移，表盘显示真实本地时间）；
  `!http https://api.github.com/zen` → **HTTP 200 + 正文**（真实互联网）。

### 3.3.4 资源优化（81.8% → 38.2% SRAM）
关闭 `CONFIG_ALLSYMS`（符号表 125 KB）、GPX 缓冲 4096→1024 点（137 KB）、航迹环 2048→1024（32 KB）；
并新增 `APP_DIAG_VERBOSE` 编译开关让发布固件串口静默。

### 3.3.5 现代化 UI（v4.0）
深黑 AMOLED + 每页强调色；自研**圆润笔画数字**（7 段 + 半圆端点）替代七段数码管；渐变进度弧（圆头端点）；
胶囊按钮/状态 pill；发丝卡片；字距标签；**AI 通知卡片按文本 1–3 行自适应、点按即收起且不误触下方按钮**。
硬性规范（四角零内容、底部宽元素 y≤390、无长按、仅 KEY 翻页、辅助文字 2×）全部满足。

### 3.3.6 诊断与验证体系（AI 协作的基础设施）
- `tools/listen_ui.py` + `src/devshot.h`：实机抓帧（每 20 s 一帧）；
- `tools/ui_check.py`：主色统计 + ASCII 缩略图（无需视觉模型即可量化核对布局）；
- `tools/link_test.py` / `mic_test.py` / `gateway.py`：链路与音频**在线调试工具箱**（可在不重新烧录的情况下扫参数）；
- 磁数据拟合脚本与原始 JSON 入库（`docs/evidence/measurements/`）。

## 3.4 AI Coding 实践（本项目的工作方式）

- **自建 Skill**：`skills/huangshan-watch-dev/SKILL.md` 固化"本地改→VM 编译→烧录→串口/截图验证"全流程、
  硬件拓扑、硬性 UI 规范与全部踩坑（含本次新增的"RX 1 字节深""NSH 抢占""PM 门控 codec 时钟"等）。
- **日志**：使用大赛采集器导出真实会话至 `logs/DingXu-Hub/`（manifest 由官方工具生成）。
- **AI 的实际贡献（可核对）**：
  1. 逐行比对官方库/数据手册定位磁校准根因，并设计"物理自证"验收（半径=地磁总场）；
  2. 通过"设备端逐帧诊断 + PC 端回显测量"定位串口丢字节规律，进而设计节流写 + 帧协议；
  3. 自动截图 + OCR/像素统计复核 6 页 UI 与 AI 卡片；
  4. 在线扫参工具（`!mic sweep`）把硬件 bring-up 从"反复烧录"变为"一条命令出表"。

## 3.6 创新点与不足

**创新点**
1. **端侧主动 Agent + PC 中继的务实架构**：在无 WiFi、BT-PAN 不可用的硬件上，用"帧协议 + PC 网关"
   实现时间同步/HTTP/LLM，且诚实标注数据出口；
2. **校准的物理自证验收**：以"拟合半径必须等于当地地磁总场"作为硬门限，把"看起来能用"变成"物理上正确"；
3. **面向"坏链路"的工程加固**：识别出 RX 1 字节深/NSH 抢占两个隐蔽根因，用节流写 + CRC/ACK/重传彻底解决历史丢命令问题。

**不足（如实说明）**
1. 无 RTC：时间依赖网关同步，重启回到演示日期；
2. 麦克风 bring-up 未完成（内部 codec 的厂商启动序列不在公开 SDK 中，已排除 12 组时钟配置与通道映射）；
3. 轨迹为 IMU 航位推算（无 GNSS），长距离累积误差；
4. 电池监测未实现（AW32001 在 I2C 上，驱动未写）。
